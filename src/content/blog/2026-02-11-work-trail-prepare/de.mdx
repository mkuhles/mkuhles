Laut Drupal‑Dokumentation definierst du ein Sub‑Theme wie ein normales Theme und gibst im `.info.yml`‑File den Schlüssel `base theme` an.  Die Starterkit‑Funktion oder Drush (`drush generate theme`) kann ein Grundgerüst erzeugen.

>   * Überschreibe das Twig‑Template für den Inhaltstyp „Fahrzeug“ (zum Beispiel `node--vehicle.html.twig`), um die Felder Erscheinungsdatum und Preis individuell zu formatieren (z. B. Währungsformat oder Datumsausgabe).

> ### Beispielaufgabe 2 – Backend‑Modul mit eigener Route und 404‑Logik (ca. 2 Stunden)
>
> **Aufgabe:** Entwickle ein eigenes Modul, das eine benutzerdefinierte Seite ausliefert und unter bestimmten Bedingungen einen 404‑Fehler zurückgibt.
>
> 1. **Modul‑Skeleton:**
>
>   * Erstelle in `modules/custom/vehicle_checker` die Dateien `vehicle_checker.info.yml` (mit Name, Typ = „module“ und Core‑Version) und `vehicle_checker.routing.yml`.  Laut Drupal‑Doku bestehen einfache Seiten aus zwei Schritten: man legt im Routing‑YAML eine Route mit Pfad und Controller‑Zuweisung an und implementiert dann einen Controller.
>   * Definiere eine Route wie `vehicle_checker.detail` mit dem Pfad `/vehicle-check/{node}` und weise als Controller `VehicleCheckerController::detail` zu.  Setze als Requirement eine Berechtigung wie `access content`.
>
> 2. **Controller implementieren:**
>

>
>   * Achte darauf, dass die Seite gecacht wird (z. B. mit `#cache`‑Einträgen), und teste die 404‑Logik mit verschiedenen Erscheinungsdaten.

  defaults:

## Controller implementieren

Da wir im Routing den `{node}`-Parameter als `entity:node` typisiert haben, bekommen wir im Controller direkt ein Node-Objekt injiziert.

Datei:
`web/modules/custom/vehicle_checker/src/Controller/VehicleCheckerController.php`

```php
<?php

namespace Drupal\vehicle_checker\Controller;

use Drupal\Core\Controller\ControllerBase;
use Drupal\node\NodeInterface;
use Symfony\Component\HttpKernel\Exception\NotFoundHttpException;

class VehicleCheckerController extends ControllerBase {

  public function detail(NodeInterface $node) {

    // Sicherheit: Nur für den richtigen Content-Type.
    if ($node->bundle() !== 'cars') {
      throw new NotFoundHttpException();
    }

    // Feld auslesen (Machine Name ggf. anpassen).
    $release_date = $node->get('field_release_date')->value;

    if ($release_date) {
      $year = date('Y', strtotime($release_date));

      // Wenn Erscheinungsjahr 2020 → 404
      if ($year === '2020') {
        throw new NotFoundHttpException();
      }
    }

    return [
      '#theme' => 'vehicle_checker_detail',
      '#node' => $node,
      '#cache' => [
        'contexts' => ['route'],
        'tags' => $node->getCacheTags(),
      ],
    ];
  }

}
```

Wichtig:

* `bundle()` muss deinem Content-Type-Machine-Name entsprechen (`cars` oder `vehicle` – je nachdem, was du wirklich angelegt hast).
* `field_release_date` ggf. anpassen.
* Durch Übergabe der Node-Cache-Tags wird die Seite automatisch invalidiert, wenn das Fahrzeug aktualisiert wird.

## Twig-Template für die Ausgabe

Damit wir nicht einfach nur `#markup` zurückgeben, legen wir ein kleines Twig-Template an.

Datei:
`web/modules/custom/vehicle_checker/templates/vehicle-checker-detail.html.twig`

```twig
<article class="vehicle-checker-detail">
  <h1>{{ node.label }}</h1>

  <p><strong>Preis:</strong>
    {{ node.field_price.value|number_format(2, ',', '.') }} €
  </p>

  <p><strong>Erscheinungsdatum:</strong>
    {{ node.field_release_date.value|date("d.m.Y") }}
  </p>

  {% if node.field_brand.entity %}
    <p><strong>Marke:</strong>
      {{ node.field_brand.entity.label }}
    </p>
  {% endif %}
</article>
```

## Fazit

Als Übung für ein Probearbeiten ist das ziemlich realistisch.

* sauberes Setup mit DDEV + Composer
* strukturiertes Arbeiten mit Config-Export
* Site-Building (Content-Type, Taxonomie, Views)
* Theming (Subtheme + Twig-Override)
* Backend-Verständnis (Routing, Controller, 404-Logik, Cache)

In einem echten Projekt würde ich:

* Business-Regeln nicht hart codieren („2020“) sondern konfigurierbar machen.
* Tests ergänzen (Kernel-Test für die 404-Logik).
* Die Route ggf. über AccessCheck lösen statt Exception.

In vier Stunden ist das machbar – vorausgesetzt, man hat die Drupal-Workflows schon ein paar Mal gemacht.
